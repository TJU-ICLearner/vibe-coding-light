# Vibe Coding Light 多状态与透明 GIF 桌宠设计

日期：2026-10-22
状态：待用户审阅

## 目标与已确认范围

用户可以继续只选一张图片制作桌宠，也可以为工作、等待、出错和完成状态分别选择不同图片。每个位置既可放静态图片，也可放已有透明背景的 GIF 动图。未指定状态图片时使用默认图片；`idle` 和 `unknown` 都使用默认图片。状态来源仍是应用现有的 Claude Code / Codex 状态事件。

静态 PNG/JPEG 延续现有本地自动去背景与透明 PNG 导入方式。第一版动图仅支持透明 GIF，不对 GIF 逐帧自动抠图，不引入云端服务。桌宠导入仍以 macOS 为目标：自动去背景要求 macOS 14+，已有透明素材可在 macOS 12–13 使用；Windows/Linux 的现有内置猫和状态显示继续工作。

## 方案选择

| 方案 | 优点 | 代价 | 决定 |
| --- | --- | --- | --- |
| 一只桌宠包含默认素材与可选状态素材 | 单图和多状态共用选择、预览和保存流程；状态缺图可自然回退 | 需要扩展宠物包、命令与渲染器 | 采用 |
| 每个状态保存一只独立桌宠并自动切换 | 可复用当前单图存储 | 宠物列表、删除和切换语义混乱 | 不采用 |
| 要求用户提供精灵图或视频 | 可精确控制帧播放 | 制作门槛高，偏离“上传图片”的目标 | 不采用 |

## 用户流程

1. 设置页提供“单图”和“按状态”两种制作方式。“单图”延续目前的导入、抠图、预览、大小位置调整和保存操作；也可选透明 GIF。“按状态”先设置必需的默认素材，再按需为工作、等待、出错、完成状态设置素材。切换方式时保留当前窗口中的草稿；界面明确提示保存为单图时只写入默认素材。
2. 每个素材位置可选择 PNG、JPEG 或 GIF。PNG/JPEG 可走现有自动去背景流程；已有透明 PNG 可直接使用。GIF 只显示“保留透明背景”，不提供自动抠图。每个位置显示原图、处理后的预览及自己的错误提示。
3. 状态预览按钮沿用现有五个状态。未上传专属素材时，预览显示默认素材及该状态的静态图轻动效。GIF 按文件内的帧时序播放，不叠加静态图的状态轻动效；点击桌宠时仍可使用通用短促摇晃反馈。
4. 文件选择和预览不更改当前桌宠。保存成功后原子写入新桌宠包、选中它，并通知桌宠窗口立即按当前状态显示。现有已保存桌宠仍可选择或删除；第一版更换某只已保存桌宠的素材通过新建桌宠完成。

## 素材处理与限制

静态图继续由现有处理器裁切并归一化为 256×256 透明 PNG。GIF 保留原始帧、帧时序和循环设置，渲染时在 128×128 桌宠窗口中按比例缩放；用户使用该桌宠共享的大小与位置参数调整整体显示。建议用户上传主体占画面比例相近的各状态素材，避免切换时视觉尺寸跳变。

前端先检查文件类型和文件大小，Rust 再按文件内容重新校验。静态图维持单文件 10 MiB、最大边长 4096 像素。GIF 单文件上限 10 MiB、宽高各不超过 1024 像素、帧数为 2–120，所有解码帧的 RGBA 像素总量不超过 64 MiB；一只桌宠全部将被保存的素材字节总量不超过 25 MiB。GIF 必须包含可见主体，合成后的各帧不能带不透明整幅背景。损坏、超限或无透明背景的 GIF 明确报错，不保存任何部分完成的桌宠包。保存时后端再次验证预览素材，不能仅信任前端标注的 MIME 或扩展名。

第一版不裁切或重新编码 GIF，因此预览需要如实显示其原有边距、颜色和播放速度。透明 GIF 的色彩与边缘质量取决于用户提供的文件。

## 宠物包与向后兼容

现有 `schema_version: 1` 的 `manifest.json` 和 `pet.png` 保持可读，加载时解释为只有默认素材，不改写用户文件。新保存的宠物包使用 `schema_version: 2`，清单保留 ID、名称、缩放、偏移和创建时间，另记录各位置的素材类型（`png` 或 `gif`）。资源文件名由固定位置和类型派生，例如 `default.png`、`working.gif`，清单不能提供任意路径。默认素材必需，其他位置可缺省。

保存时在 `pets/` 下的临时目录写入并验证全部资源和清单，再一次性重命名为正式目录，最后更新选中 ID。加载时逐个校验文件、类型与大小；若清单或默认素材缺失、损坏，沿用现有逻辑回退到内置像素猫且不删除用户文件。已声明的可选状态素材缺失或损坏时，仅该状态使用默认素材，并在设置页提示该资源需要重新创建。旧版本应用无法理解新格式时可回退内置猫，但旧 `schema_version: 1` 宠物包不会被迁移或删除。

Rust 命令向桌宠窗口提供已验证的素材及其 MIME 数据 URL，前端不直接读取任意本地路径。选中桌宠时加载素材集合；状态切换只在对应素材改变时更新 `<img>` 的 `src`，避免重复状态事件不断重播 GIF。重新进入某个 GIF 状态时从首帧播放。`completed` 的静态图继续播放一次现有跳跃动效，之后恢复轻缓待机动效；GIF 则按自身循环设置播放，直到状态改变。`unknown` 始终映射默认素材，托盘的未知状态提示不变。

## 组件边界

- 设置页维护每个素材位置的导入草稿、处理方式、预览与错误状态，防止较早的异步预览结果覆盖较新的选择。
- Rust 素材处理模块负责格式识别、静态图处理、GIF 全帧校验和资源预算；存储模块负责版本兼容、固定文件名、原子保存、选择与删除。
- 桌宠渲染器负责状态到素材的选择、缺图回退、静态动效及 GIF 播放；不解析清单或访问文件系统。
- 内置像素猫的精灵图与互动覆盖素材保持原有路径。图片/GIF 桌宠继续使用不依赖内置猫固定坐标的点击反馈。

## 验收与测试

1. 旧版单图桌宠、当前选中 ID 和内置猫在升级后仍能显示；新建单图桌宠的行为与当前版本一致。
2. 多状态桌宠在五种状态间正确切换；未设置的状态和 `unknown` 使用默认素材；重复收到同一状态不重置 GIF 播放。
3. 透明 GIF 在单图模式及任一专属状态位置可预览、保存、播放和重启恢复；静态图仍能自动去背景或保留透明 PNG。
4. 损坏 GIF、不透明 GIF、超尺寸/帧数/解码预算、格式伪装、总资源超限和写入失败均给出错误，当前已选桌宠及旧资源保持不变。
5. Rust 测试覆盖 GIF 校验、版本 1/2 读取、原子保存与失败回退；前端测试覆盖草稿竞态、状态映射、素材回退和 GIF 不重复重启；macOS 实机检查预览、桌面状态切换与重启持久化。

## 本次不包含

GIF 逐帧自动抠图、APNG/动态 WebP/视频导入、为每个状态单独设置缩放与偏移、就地编辑已保存桌宠、跨平台图片导入和云同步。
