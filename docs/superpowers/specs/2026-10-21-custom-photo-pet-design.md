# Code Light 自定义图片桌宠设计

日期：2026-10-21
状态：待用户审阅

## 目标与范围

用户选择一张图片后，在 Code Light 内完成本地去背景、裁切预览和保存，让原图主体成为桌宠。桌宠通过轻量位移动效回应现有的 AI 编程状态。第一版保留原图风格，不生成新的角色画稿或多帧像素素材，也不上传图片。

第一版优先支持 macOS。自动去背景要求 macOS 14 或更新版本；macOS 12–13 可导入已有透明背景的 PNG，继续使用现有内置像素猫。Windows 和 Linux 继续使用现有桌宠和状态功能，本次不开放图片导入。应用启动和现有功能的最低系统版本不因该功能提高。

## 方案选择

| 方案 | 收益 | 代价 | 决定 |
| --- | --- | --- | --- |
| macOS Vision 本地前景分离 | 无图片上传和模型下载；安装包体积变化小 | 自动抠图限 macOS 14+ | 第一版采用 |
| 跨平台本地模型 | 三平台同一套自动抠图能力 | 模型文件、推理运行时、打包与模型授权需要额外处理 | 后续评估 |
| 云端抠图服务 | 平台一致，应用端集成较轻 | 图片上传、服务费用、网络依赖 | 第一版不采用 |

宠物资源和状态映射采用 Code Light 自己的最小格式，借鉴 PixelPal 的宠物包思路，但不复制其完整状态机；现有 agent 状态逻辑继续作为唯一的状态来源。

## 用户流程

1. 托盘菜单新增“自定义桌宠”，打开独立设置窗口；已有 128×128 透明桌宠窗口不承担编辑操作。
2. 用户选择 PNG 或 JPEG。界面显示原图、处理后的透明预览、主体在桌宠窗口中的实际大小，并提供大小与水平/垂直位置调整。
3. macOS 14+ 默认执行本地自动去背景；如果图片已有透明通道，用户也可以直接采用原始透明区域。macOS 12–13 只接受带实际透明区域的 PNG。处理失败时展示原因，允许换图；当前桌宠保持不变。
4. 预览可切换待机、工作、等待、出错、完成五种状态。用户确认后保存并立即应用。设置中可切换已保存的图片桌宠、恢复内置像素猫，并删除不再需要的图片桌宠。

选择文件或完成预览不会修改当前宠物。只有“保存并应用”和明确的切换/删除操作会改变持久状态。

## 组件与数据流

### 设置窗口

新增独立 WebView 设置窗口及其前端入口。它负责文件选择、尺寸与位置控制、状态预览、宠物列表和错误反馈。文件在前端读取后传给 Rust 命令；前端先检查扩展名和大小，Rust 再独立校验文件字节、图片尺寸与解码结果。第一版限制输入 10 MiB、最大边长 4096 像素，防止异常图片占用过多内存。

### 图片处理

Rust 后端提供预览处理命令。macOS 14+ 通过一层 macOS 原生桥接调用 Vision 的前景实例遮罩，在本机生成透明 PNG。处理后按主体边界裁切，按比例放入 256×256 透明画布，保留透明边距，供 128×128 桌宠窗口显示。用户调整大小和位置时只改变渲染参数，不重复运行抠图。

自动分离可能找不到主体或选错主体。第一版选择遮罩中面积最大的前景实例，并让用户在保存前查看结果；没有可用遮罩时返回可理解的错误，不保存空白宠物。多主体选择与手工橡皮擦留待后续版本。

### 宠物存储

应用数据目录中的 `pets/<id>/` 保存处理后的 `pet.png` 与 `manifest.json`。清单包含格式版本、唯一 ID、显示名称、缩放和位置参数、创建时间；原始照片不留存。单独的偏好设置记录当前选中的 ID，内置像素猫以保留 ID `builtin-cat` 表示。

保存流程先在临时目录写入并验证完整宠物包，再将该目录重命名为正式宠物目录，最后更新当前选择。启动时校验清单和 PNG；找不到、损坏或版本不兼容时回退到内置像素猫，不删除用户文件。只允许读取应用数据目录内规范化后的宠物资源，不接受清单提供的任意绝对路径。

### 桌宠渲染

现有 agent 状态事件保持不变。新增渲染适配层：内置猫仍使用现有 spritesheet；图片桌宠使用一张透明 PNG 和按状态命名的 CSS 动效。两种渲染都接受同一组状态：`idle`、`unknown`、`working`、`waiting`、`error`、`completed`。`unknown` 显示待机动作，托盘继续使用现有灰色未知状态提示。

图片桌宠的动作限制在桌宠窗口内：待机慢速呼吸，工作轻弹，等待轻摆，出错短促抖动，完成单次跳跃后回待机动作。切换宠物时取消旧动画并即时应用当前 agent 状态。现有鞭打等互动素材按内置猫位置绘制；使用图片桌宠时改为通用短促摇晃反应，不显示这些固定坐标的覆盖素材。拖动窗口与显示/隐藏行为继续生效。

Rust 后端向桌宠窗口返回已验证且缩小后的图片数据和配置；前端不直接拼接文件路径或扩大文件系统权限。保存、切换、删除时发出宠物变更事件，桌宠窗口重新加载当前宠物。

## 错误与兼容性

- 不支持的格式、超限文件、损坏图片、无透明区域的旧版 macOS 输入、未识别到主体、保存失败：设置窗口显示具体原因，当前选择不变。
- 自动抠图仅在 macOS 14+ 可用；旧版 macOS 的设置界面明确说明透明 PNG 导入方式。
- Windows/Linux 构建不能依赖 macOS 专用代码；已有内置猫和状态指示保持可用。
- 图片和宠物配置只在本机处理与保存，不引入网络调用或 API 密钥。
- 设置窗口关闭后桌宠继续运行；重启后恢复上次有效选择。

## 验收与验证

1. macOS 14+ 选取含背景的 PNG/JPEG，可见透明预览；保存后在 128×128 桌宠窗口正确显示，重启后仍选中。
2. 状态事件分别触发五种轻量动作；`unknown` 不误报为工作或完成。切换到内置猫后原有帧动画仍工作。
3. 透明 PNG 可跳过自动去背景；在 macOS 12–13 上可导入，普通不透明图片给出明确提示。
4. 文件超限、损坏、没有可用前景、写入失败，以及清单或图片被外部破坏时，不出现空白桌宠，不丢失当前有效宠物。
5. 删除当前图片桌宠时先切回内置猫；删除其他宠物不改变当前显示。
6. Rust 测试覆盖输入校验、清单解析、路径约束和持久化回退；前端测试覆盖状态到动效的映射与切换；在 macOS 上用含背景、透明、多主体样图手动检查预览和实际桌面表现。运行现有构建、Rust 测试和 lint 检查。

## 本次不包含

AI 重新绘制角色、多帧 spritesheet 生成、手动蒙版编辑、跨平台自动抠图、云同步、宠物包导入导出、多桌宠同时运行。后续版本可沿用清单版本号扩展这些能力。
