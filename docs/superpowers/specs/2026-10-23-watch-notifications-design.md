# Vibe Coding Light 可选手表通知设计

日期：2026-10-23
状态：待用户审阅

## 目标与范围

用户在 macOS 上运行 Vibe Coding Light 时，可以自行选择哪些 Claude Code 和 Codex 事件通过 Bark 发送到 iPhone，并按 Apple 的通知规则显示在 Apple Watch。通知总开关、来源开关和事件开关共同决定是否发送；任何一层关闭都不自动发送。第一版只支持 Bark，应用退出后不继续推送，也不安装独立常驻服务。现有桌宠与托盘状态继续独立工作。

本设计沿用应用已安装的 Claude Code / Codex Hook，新增逐会话事件通道、额度读取器、通知决策器和 Bark 发送器。Hook 只记录本地事件，不直接联网。用户可在应用内发起一次明确的测试推送。

## 方案选择

| 方案 | 优点 | 代价 | 决定 |
| --- | --- | --- | --- |
| Vibe Coding Light 统一处理事件和 Bark 推送 | 开关、密钥、去重、语言与错误提示集中管理 | 应用必须运行 | 采用 |
| 各 Hook 直接调用 Bark | 无需应用常驻 | 密钥和规则散落在脚本中，难以统一去重 | 不采用 |
| 另装 AgentWatch 服务 | 可独立于桌宠运行 | 增加安装、配置和维护步骤 | 不采用 |

## 设置与用户流程

菜单栏新增“通知设置 / Notification Settings”，打开独立设置窗口，随应用语言在中文和英文间切换。窗口分为连接、来源、事件和额度四组，并显示 Claude、Codex 各自的 Hook/额度接入状态。

1. “手表通知”总开关默认关闭。Claude Code 与 Codex 来源开关默认开启；“权限待批准”“问题待回答”“本轮回复完成”“执行错误”默认开启；额度的 80%、50%、20%、0% 四个档位及“额度恢复”默认关闭。用户可独立调整每个开关。所有设置本地持久化；总开关开启而所有事件均关闭时，页面明确显示“当前没有选中的通知类型”。
2. 用户输入 Bark 设备密钥，应用将密钥保存在 macOS 钥匙串。设置文件仅保存非敏感开关和连接状态，不保存密钥；编辑框默认不回显完整密钥。只有总开关开启且密钥已保存时，“发送测试通知”按钮可用。按钮发出固定测试文案，明确告知发送结果。
3. Claude/Codex Hook 尚未安装时，设置页指向应用现有的安装操作。Claude 额度档位开启时，应用安装本地状态栏包装命令以获取官方 `rate_limits` 字段：它将同一份输入交给原有状态栏命令，并原样保留其输出。应用保存原配置；仅在配置仍指向自己的包装命令时才自动恢复，避免覆盖用户之后的修改。Claude 额度全部关闭时移除自身包装命令。若配置受管理策略限制或无法安全包装，显示“Claude 额度暂不可用”，其他通知仍可使用。
4. 默认推送文案仅包含来源、事件类型与额度周期/剩余百分比。例如“Codex · 5 小时额度剩余 20%”。不发送提示词、项目路径、命令、错误原文或会话内容。通知语言使用发送时的应用语言。

Apple Watch 的实际显示位置由 iPhone 与手表状态及通知设置决定；应用只负责将消息交给 Bark，不能保证每条都直接显示在手表上。

## 事件语义与覆盖范围

“权限待批准”来自 Claude 的 `permission_prompt` 通知或 Codex 的 `PermissionRequest` Hook；“问题待回答”只在对应客户端明确暴露待输入事件时发送。Claude 可使用 `elicitation_dialog` 等通知；Codex 的部分界面内提问未必有可观察 Hook，设置页必须说明这个覆盖边界，不用解析自由文本来猜测用户是否需要回答。

“本轮回复完成”来自各客户端的 `Stop` 事件，表示当前一轮停止，不宣称整个项目或用户任务已经完成。对完成事件先等待 3 秒；若同一会话继续工作或进入等待状态，就取消这条通知。逐会话、逐轮识别完成事件，其他会话的高优先级状态不能遮住它。事件文件 ID 用于防止重复消费；通知决策器还要按来源、会话、轮次及事件类别合并重复 Hook。客户端没有轮次 ID 时，以同一会话从工作/等待进入停止的状态转换为一轮边界。

“执行错误”只基于明确的失败信号：Claude 的 `PostToolUseFailure`，以及 Codex `PostToolUse` 中可明确识别的失败结果。普通工具输出中的“error”字样不构成失败。相同会话内的连续失败合并，30 秒内最多通知一次。通知用“执行遇到错误”，不声称智能体已停止；若无法可靠区分成功与失败，则不发送错误通知。

现有 `state-changed` 只在汇总状态改变时发出，因此不能作为推送唯一来源。Hook 为每次可通知事件写入带唯一 ID、来源、会话 ID、事件类别和时间的独立本地记录；应用逐条消费。Hook 写入不能等待网络，也不能因 Bark 故障阻塞 Claude 或 Codex。启动时把既有记录作为基线，不补发应用未运行时积累的旧事件。记录有大小和保留时间上限，处理后清理。

## 额度数据与提醒规则

Claude Code 使用官方状态栏 JSON 的 `rate_limits.five_hour` 与 `rate_limits.seven_day`，两者分别标为“5 小时”和“7 天”。字段只在客户端提供时有效；例如订阅类型不支持、首次 API 响应前或窗口过期后，额度显示暂不可用。状态栏包装命令只提取额度百分比与重置时间，不保存完整输入 JSON。

Codex 通过本机 Codex App Server 的 `account/rateLimits/read` 获取限额；优先使用 `rateLimitsByLimitId`，缺失时使用兼容的单桶 `rateLimits`。每个桶的 `primary`、`secondary` 窗口独立处理，按 `limitName` 或桶标识与 `windowDurationMins` 标明来源和周期。只有已使用 Codex 服务支持的登录方式且接口返回有效百分比时才启用；API Key 等无额度数据的模式显示暂不可用。Codex 额度读取仅在总开关、Codex 来源及至少一个额度档位均开启时运行，目标间隔 5 分钟，网络失败时不虚构百分比。

百分比统一定义为剩余量 `max(0, min(100, 100 - usedPercent))`。80%、50%、20%、0% 分别有独立开关。每个来源、额度桶、额度周期与有效重置周期独立提醒；只有剩余量从档位上方降到档位或以下才触发。首次获取数据或刚开启某档时只建立基线，不补发已经越过的档位。如果一次采样越过多个开启的档位，只发送最低的那个，并将同时越过的较高档位记为已处理。0% 可由已用 100% 或服务明确报告额度耗尽触发。

同一额度周期内每档最多提醒一次；记账信息跨应用重启保存。仅在旧周期确已结束且新采样显示剩余量高于此前最低的已提醒档位后重新武装，不能因为 `resetsAt` 小幅变化就重复提醒。可选“额度恢复”只在此前周期确有额度提醒、上述恢复条件成立时发一次，文案同样包含来源和周期。Claude 与 Codex 同时有短周期和长周期时分别提醒，不合并成一个百分比。

## 推送、失败与隐私

Rust 通知决策器按总开关、来源、类别、额度档位、事件去重和有效期过滤，再向 Bark `POST /push` 发送 JSON；设备密钥只放在请求体，不拼入 URL、日志或 Hook 文件。只接受 HTTPS Bark 服务地址，第一版使用 Bark 默认服务。关闭任一开关立即阻止后续自动推送；删除密钥后无法发送。

连接建立前明确失败的请求可短暂重试；请求超时或已经发出而结果不明时不自动重试，优先避免重复通知。待处理事件超过 2 分钟、完成/错误事件超过 10 分钟即丢弃；应用启动前的事件一律不补发。推送失败只在本机设置页显示简短诊断，不转化为另一条手表通知，也不影响桌宠状态。事件 ID 与额度档位的本地记账应避免进程重启后重复推送；Bark 与 Apple 端的最终送达无法由应用保证。

通知设置与测试按钮只向通知窗口暴露必要的 Tauri 命令；密钥读取和推送在 Rust 侧完成。配置文件采用原子写入与合理文件权限。卸载或关闭通知不会删除现有桌宠、会话状态或用户自有的 Claude 状态栏脚本。

## 组件边界

- Hook 事件记录器：把 Claude/Codex 可观察事件规范化并原子写入本地事件记录，不处理用户开关与网络。
- 额度适配器：分别读取 Claude 状态栏快照和 Codex App Server，输出带来源、桶、窗口、剩余比例、重置时间的统一快照；缺字段返回不可用。
- 通知决策器：独立于 UI，根据设置、事件与额度快照计算是否应发送，负责阈值、延迟、去重、有效期和持久化记账。
- Bark 客户端与钥匙串存储：只负责凭据读写、测试发送、JSON 推送和明确的连接错误，不解释代理事件。
- 通知设置窗口：编辑开关、展示接入和发送状态；沿用现有应用语言，不直接读取密钥或会话文件。

## 验收与测试

1. 总开关、两个来源、四类事件、四个额度档位及额度恢复均可独立控制；任何相关开关关闭时不自动推送；测试推送必须由用户主动点击。
2. 两个会话交错出现等待、完成和错误时，各自事件均可正确处理；同一轮的重复 Hook 不重复推送；完成后 3 秒内继续工作则不发送完成提醒。
3. Claude 5 小时/7 天与 Codex 每个可用额度桶和窗口分别跨档提醒，通知标明来源及周期；一次跨多档只发送最低档；重启不重复；额度重置后重新武装；首次启用不补发。
4. 缺失额度、未登录、不支持的登录方式、损坏数据、钥匙串失败及 Bark 网络故障均显示可理解的本地状态，不编造百分比，不泄露凭据，不阻塞 Hook 或桌宠。
5. 已有 Claude 状态栏的配置与输出在启用、关闭额度接入后保持一致；若用户在接入期间自行修改配置，应用不覆盖其修改。
6. 自动测试覆盖通知决策器、事件记录/消费、额度适配器、设置持久化、双语文案以及模拟 Bark 响应。macOS 实机的 Bark 到 iPhone/Apple Watch、钥匙串和现有状态栏共存由用户按检查清单验证；不使用 Computer Use。

## 第一版边界

不支持直接控制 Apple Watch 的通知路由、脱离 Vibe Coding Light 运行的常驻推送、云端推送账户、回复手表通知来批准权限、解析聊天内容推断任务成败，以及 Claude/Codex 未公开事件的全覆盖保证。
