# 可连续操作的菜单栏弹窗设计

## 目标

macOS 菜单栏图标左键打开可停留的弹窗。用户切换登录时启动、自动检查新版本或语言，以及手动检查版本后，弹窗继续显示最新状态；无需反复点击菜单栏图标。

## 方案

已比较两种方式：保留原生菜单并另开应用设置窗口，改动较小但仍需离开菜单；用 Tauri Webview 构建菜单栏弹窗，改动较多但符合连续操作的预期。用户选择后者。macOS 左键使用新弹窗，右键保留当前原生菜单作为备用；Windows/Linux 保持现状。

## 交互

- 弹窗位于菜单栏图标下方，随图标所在屏幕定位并限制在可见区域内。再次点击图标、点击弹窗外或按 Esc 收起。
- 保留现有入口：显示／隐藏桌宠、摸摸、自定义桌宠、通知设置、Claude/Codex Hook、当前会话、语言、登录时启动、自动检查新版本、检查新版本、新版本下载和退出。
- 开关、语言切换与检查版本不收起弹窗；检查过程及结果在原位更新。打开设置窗口、下载页或退出时收起。错误在原位显示，双语文案一致。
- 当前会话仅展示状态，与现有原生菜单一样不可点。右键原生菜单保留相同功能。

## 实现边界

- 后端提供只给 `tray_panel` 窗口调用的状态和动作命令；动作与原生菜单共用一套处理逻辑，避免两套状态漂移。
- 弹窗只读取可展示的会话摘要、选项状态和版本结果，不读取 Bark 密钥或任务原文。
- 使用现有 Tauri、Rust 和前端栈，不添加新依赖。页面可滚动并支持键盘操作。
- 此轮以 macOS Apple Silicon RC5 发布；桌宠全屏显示、拖动和 Bark 逻辑继续沿用 RC4。

## 验证

单元测试覆盖连续点击动作后弹窗保持显示、版本检查异步状态、双语切换、Esc 收起和后端窗口权限；构建与 Rust／前端／Hook 测试全部通过。安装包验证版本、签名与校验和。弹窗在不同屏幕和 macOS 全屏空间中的实际位置由用户实机验证。
