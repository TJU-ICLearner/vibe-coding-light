# RC 版 Bark 全事件测试台设计

## 目标与范围

让用户无需耗尽额度、等待权限请求或制造真实错误，就能逐项验证 Vibe Coding Light 的 Bark 通知。测试台仅用于 RC 版；正式版发布前删除测试台入口及模拟发送命令。保留现有普通 Bark 连接测试。

## 方案选择

- **逐项按钮，遵循当前设置（已选择）**：权限、提问、完成、错误、剩余 80%／50%／20%／0%、额度恢复旁各有“测试”按钮。结果直接显示“已提交给 Bark”“已跳过：原因”或“发送失败”。用户能验证当前开关、免打扰、文案与 Bark 发送。
- 集中选择事件后测试：页面较紧凑，但无法逐项检查；未采用。
- 强制发送且忽略设置：只能验证文案和通道，无法发现被开关或免打扰拦下的事件；未采用。

## 交互

通知设置页增加醒目标明“仅 RC 测试”的区域。区域顶部选择通知来源（Claude Code／Codex）；额度测试另可选择周期（5 小时／7 天）。每个事件或额度档位旁有独立测试按钮，同一时间仅运行一次测试。结果显示在按钮附近并记录到现有通知诊断列表，明确标记为模拟测试。中英文界面完整翻译。

测试仍按当前总开关、来源开关、事件／档位开关和免打扰判断。被跳过时显示具体原因；未保存 Bark 密钥或 Bark 拒绝／网络错误时显示对应失败原因。测试消息标题带“[测试]”或“[TEST]”，正文使用虚构的任务、命令、问题或错误样例，沿用该事件当前语言的自定义标题和正文模板。额度消息带选择的来源、周期和模拟剩余百分比。测试入口不读取或发送真实任务原文。

## 实现边界

后端只接受固定的来源、事件及两个额度周期，通过现有候选过滤、模板渲染和 Bark 客户端发送。模拟事件不进入真实 Hook 事件队列、不改变额度观察值、阈值去重账本或会话状态。仅通知设置窗口可调用命令；RC 版本可用，正式版本即使遗漏入口也拒绝模拟发送。现有“额度可读取”状态继续证明额度源可读；模拟发送验证过滤、文案和 Bark 通道，不宣称验证真实额度何时跨档。

## 验证与退出条件

测试各事件按钮的映射、来源与周期、双语文本、跳过与失败结果；检查真实额度账本和会话不变。用本机安装包确认测试台显示，并由用户在手机上验证各类 Bark 消息。正式版发布任务包含删除测试台 UI、模拟命令和专用文案；保留普通 Bark 连接测试。
