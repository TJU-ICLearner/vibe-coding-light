# 手表通知 macOS 实机检查

日期：2026-10-23。自动测试覆盖事件文件、判定器、额度解析、Bark 模拟响应和双语设置。以下项目需要用户在自己的 Mac、iPhone、Apple Watch 上确认；目前均**未做实机验证**。

测试前：在 iPhone 安装 Bark 并允许通知；在 Bark 中取得设备密钥；确保 Apple Watch 已配对并允许 Bark 通知。Apple 的通知路由通常会根据 iPhone 锁定状态和手表佩戴/解锁状态变化，应用无法强制一条消息直接显示在手表上。

| 检查 | 操作与预期 | 实际结果 |
| --- | --- | --- |
| 首次打开 | 菜单栏打开“通知设置”；总开关关闭、事件默认开启、额度档位默认关闭；未输入 Bark 密钥时测试按钮不可用 | 待填写 |
| Bark 与钥匙串 | 输入设备密钥并保存；窗口只显示“已保存”，不回显密钥；开启总开关后点“发送测试通知”，Bark 收到固定文案 | 待填写 |
| iPhone / Watch 路由 | 分别在 iPhone 解锁及锁屏、手表佩戴解锁时发送测试通知，记录通知出现的设备；这由 Apple/Bark 设置决定 | 待填写 |
| Claude 权限与提问 | 用 Claude Code 触发工具权限请求、明确的提问事件；只开启对应事件时分别收到短文案，未含提示词 | 待填写 |
| Codex 权限 | 用 Codex 触发 `PermissionRequest`；收到 Codex 权限提醒。Codex 某些界面内问题没有可观察 Hook，可能不提醒 | 待填写 |
| 完成与继续 | Claude/Codex 各完成一轮，应约 3 秒后提醒；若在这 3 秒内继续工作，应取消完成提醒 | 待填写 |
| 错误 | 触发明确的工具失败；收到“执行遇到错误”；同一会话 30 秒内连续失败最多提醒一次，普通输出中的 error 字样不提醒 | 待填写 |
| Claude 额度 | 开启 80/50/20/0 中一档，使用支持状态栏 `rate_limits` 的 Claude 订阅；设置页应显示额度可读取；5 小时和 7 天独立标注。首次采样不补发 | 待填写 / 订阅不支持 |
| Codex 额度 | 使用支持 App Server 额度接口的 Codex 登录，开启档位；不同桶、短周期、长周期独立标注；API Key-only 等无数据时显示暂不可用 | 待填写 / 登录方式不支持 |
| 额度恢复 | 开启恢复提醒，确实跨档后等待周期结束；额度回升到先前最低提醒档位上方时只提醒一次 | 待填写 / 无法在本次测试触发 |
| 语言 | 菜单栏切换中文/英文；通知设置页、测试结果及后续推送文案同步切换 | 待填写 |
| 现有状态栏 | 若原本有 Claude `statusLine`，启用额度提醒后确认其显示内容不变；关闭 Claude 额度提醒后确认恢复原配置；手动修改配置后应用不覆盖它 | 待填写 / 原本未设置 |
| 总开关与退出 | 关闭总开关或退出应用后触发 Hook，不应自动推送；再次启动不会补发退出期间的旧事件 | 待填写 |

记录问题时请附：macOS 版本、Claude/Codex 版本、Bark 版本、触发事件种类、设置页本地状态文字；请勿发送 Bark 设备密钥、提示词或完整 Hook JSON。
