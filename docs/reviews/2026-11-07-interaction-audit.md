# 2026-11-07 交互逻辑走查

本轮沿菜单栏弹窗、通知设置、桌宠设置和桌宠启动四条使用路径检查状态变化与用户操作的顺序。通过延迟返回的回归测试复现问题，再修改对应的数据写回逻辑。

| 路径 | 发现的问题 | 修复 |
|---|---|---|
| 菜单栏开关 | 操作完成后，先前发出的轮询可能把新状态覆盖为旧状态 | 过期轮询不再写回；慢轮询完成前不发起下一次 |
| 菜单栏摸摸 | 桌宠隐藏时仍可点摸摸，但看不到效果 | 弹窗与原生菜单在隐藏时禁用摸摸 |
| 通知设置 | 状态刷新或切换语言会清空正在输入的 Bark 密钥 | 重绘时保留未提交的输入、焦点和光标位置 |
| 通知设置 | 初始语言或状态读取晚于实时事件时，可能覆盖新值 | 初始结果只在没有较新事件时写回 |
| 通知设置 | 开关保存失败后仍显示为已开启，错误出现在 Bark 密钥区域 | 恢复最近一次成功保存的设置，并在设置区显示错误 |
| 桌宠设置 | 切换桌宠未完成时仍可保存新草稿，最终选中项可能与保存提示不符 | 切换或删除期间禁用保存按钮 |
| 桌宠启动 | 初始状态读取前未订阅事件，启动期间可能错过状态变化 | 先订阅，再读取初始状态；实时事件优先 |

验证：前端回归测试、TypeScript/Vite 构建、Rust 测试、Rust 格式检查和安装包构建。系统级视觉、拖动、钥匙串与 Bark 实际送达仍需在真实设备上验证；本轮未使用 computer use。
